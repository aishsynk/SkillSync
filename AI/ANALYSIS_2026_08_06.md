## System Architecture

### 3-Tier Model

```
┌─────────────────────────────────────────┐
│  Browser (frontend/)                    │
│  - HTML pages, JS API client            │
│  - SessionStorage cache (4h TTL)        │
│  - No credentials stored                │
└────────────────┬────────────────────────┘
                 │ HTTP (no secrets)
┌────────────────▼────────────────────────┐
│  Local Server (backend/app.py:8765)     │
│  - HTTP routing & RMS proxying          │
│  - Intelligence build pipeline          │
│  - Learning loop & agentic services     │
│  - Credentials in env vars only         │
└────────────────┬────────────────────────┘
                 │ HTTPS (credentials here)
┌────────────────▼────────────────────────┐
│  External RMS APIs                      │
│  https://api.koenig-solutions.com       │
│  9 verified endpoints, 21+ documented   │
└─────────────────────────────────────────┘
```

### Request Flow: Login → Intelligence → Dashboard

**Step 1: Authentication (Non-Blocking)**
```
User email → POST /auth/login
  ↓ (validates manager in RMS)
Session cookie issued immediately
  ↓ (old cache served if available)
Stale cache? Schedule background refresh (daemon thread)
```

**Step 2: Intelligence Pipeline (build_unified, 10 steps)**
```
1. Validate manager scope
2. Fetch reportees (direct + indirect) via RMS API
3-9. Parallel fetch per trainer:
     - Trainer Details (skills, courses, QubitsScore, certs)
     - Trainer Skills (by employee ID)
     - Utilization (% workload)
     - Vendor Certs (count)
     - HR Incidents (positive + negative)
     - Negative Feedback (complaints)
     - Assignments (past + upcoming)
   (Global once: Course List)
10. Normalize → Score (7 engines) → Build graphs (4 graphs) → Assemble (15+ datasets) → Cache
```

**Step 3: Dashboard Render**
```
Unified JSON (15+ datasets) → index.html
  ├─ KPIs (reportees, utilization, actions)
  ├─ Team table (current status, readiness, feedback)
  ├─ Charts (utilization, readiness, delivery pipeline)
  ├─ Calendar (training batches)
  ├─ Action queue (manager decisions)
  ├─ Unallocated demand (sales requests)
  ├─ Copilot chat + daily briefing
  └─ Capability upgrades (future skills)
```

## Caching & Freshness Strategy

### Per-Manager Cache
- **Location:** `runtime/cache/skilledge_{email_normalized}.json`
- **TTL:** 4 hours
- **Key files:** all 15+ datasets + metadata

### Freshness Metadata (Attached to Every Response)
```json
{
  "generated_at": 1722962400,              // Unix timestamp when built
  "served_at": 1722966000,                 // Current timestamp
  "cache_status": "cached|stale|live|refresh_failed",
  "cache_age_minutes": 62,
  "refresh_pending": false,                // Background refresh running?
  "last_refresh_success_at": "2026-08-06T10:00:00Z",
  "last_refresh_failed_at": null,
  "last_refresh_error": null
}
```

### Caching Flow
```
Cache exists + fresh (< 4h)
  → Serve immediately ✅

Cache exists + stale (≥ 4h)
  → Serve immediately + schedule background refresh (daemon)
  → Set refresh_pending: true
  → Frontend polls /api/refresh/status

Cache missing
  → Build fresh from RMS APIs (3 retry attempts, 1s wait between)
  → If build succeeds: write cache + serve
  → If build fails + old cache exists: serve stale + set last_refresh_error
  → If build fails + no cache: error to user

Background refresh failure
  → Error logged; cache remains; next build attempt tries live
```

## Learning Loop & Agentic Layer (Post-Workstream-3)

### Deterministic Agent (No LLM Required)
- **Tools:** 12 retrieval tools over unified payload
- **Intent classifier:** Routes questions to right tools
- **Seam for LLM:** `agent.answer()` — single point where external LLM could be plugged in later

### Closed Learning Loop
```
Manager closes action / escalates / reassigns
  ↓ (POST /api/actions/{id}/close|escalate|reassign)
Backend records decision as labeled example
  ↓ (Persist to runtime/learning/feedback.jsonl)
Learning service auto-tunes weights based on example
  ↓ (Gradient updates, clamped 0.03–0.60, renormalized)
Next scoring pass uses updated weights
  ↓ (Model versioned, timestamped)
Recommendation quality improves over time
```

### Agentic Endpoints
- `GET /api/agent/briefing` — Daily briefing (top 5 actions, upcoming demand, risk summary)
- `GET /api/agent/learning` — Learning loop status (model version, feedback count, weight drift)
- `POST /api/agent/ask` — Ask a question (context-aware answer)
- `POST /api/agent/feedback` — Rate a recommendation (input to learning loop)
- `POST /api/agent/tune` — Manually retune weights

### Frontend
- `frontend/js/agent-copilot.js` — Server-backed chat + daily briefing on dashboard
- `frontend/pages/index.html` — SkillEdge Copilot panel mounted
- Older `frontend/js/manager-copilot.js` remains for per-trainer client-side rule engine

## Security Model

✅ **Secrets never reach the browser**

1. **Credentials in backend only**
   - RMS usernames/passwords stored as environment variables
   - NOT in code, NOT in version control, NOT sent to browser

2. **Frontend API Proxy Pattern**
   - Browser: `POST /rms/{api_name}` (no credentials)
   - Backend: Adds auth tokens, calls external RMS API, unwraps response
   - Returns clean data (no envelope, no tokens)

3. **Session Management**
   - Cookie-based (issued on login, cleared on logout)
   - Lost on restart (in-memory)
   - No persistent tokens in browser

4. **Non-Blocking Auth**
   - Login issues session immediately; old cache served while rebuild runs
   - No seconds-long spinner on first load

## Error Handling & Recovery

### Intelligence Build Failure (3 Retries)
```
Attempt 1 fails
  → Wait 1 second
Attempt 2 fails
  → Wait 1 second
Attempt 3 fails
  → If old cache exists: Serve stale + set last_refresh_error
  → If no cache: Error to user
```

### Session Expiration
```
HTTP 401/403 detected
  → Redirect to /login.html?expired=1
  → Clear sessionStorage
  → Offer to re-login
```

### API Unreachable
```
RMS call timeout/failure
  → Caught in intelligence.py
  → Fallback to stale cache (if exists) with honest metadata
  → Frontend can judge data age before acting
```

## Known Gaps & Candidate Follow-Ups (Priority Order)

### 1. ⚠️ Live Smoke Test (Verification Needed)
**What:** `tests/smoke_test.py` against a running server with real RMS credentials  
**Why:** Verify end-to-end journey works (login → dashboard render → action lifecycle)  
**Impact:** High confidence in deployment readiness  
**Blocker:** Requires real RMS creds + a running server instance  

### 2. 🧹 Remove Duplicated Client-Side Scoring
**What:** Delete `_intelScore` function from `frontend/js/app.js` (line 371)  
**Why:** Scoring is canonical backend-side (shared/scoring.py); client duplicates risk model drift  
**Impact:** Single source of truth, reduced maintenance burden  
**Blocker:** None; mechanical cleanup  

### 3. 💾 Persist Sessions Beyond Process Lifetime
**What:** Back sessions with a database (SQLite, Redis, etc.) instead of in-memory dict  
**Why:** Sessions lost on restart; poor UX if server restarts during a manager's work  
**Impact:** Better UX for long-running sessions  
**Blocker:** Need to choose persistence layer + schema  

### 4. 🗑️ Wire or Delete Dead Scaffolding
**What:** `intelligence_engines/` (7 stub files) + `knowledge/` (4 graph files) have zero imports  
**Why:** Dead code confuses future maintainers; unclear if intended for future use  
**Impact:** Cleaner codebase; faster to onboard  
**Blocker:** None if deleting; needs decision if wiring (would require importing + testing)  

### 5. 🐛 Fix _read_kb_jsonl Parser
**What:** `backend/app.py::_read_kb_jsonl` mis-parses multi-line JSONL  
**Why:** `/api/knowledge/search` and `/api/knowledge/*` return empty arrays for populated KB files  
**Impact:** Knowledge endpoints now non-functional; blocks future KB-based features  
**Blocker:** Parser needs to handle line-buffered reads or use a proper streaming JSONL library

| 2026-08-03 | Availability verdicts cap confidence ≤60 when signals conflict | False certainty (e.g., conf 100 for 24.6%-utilized trainer) erodes trust |
